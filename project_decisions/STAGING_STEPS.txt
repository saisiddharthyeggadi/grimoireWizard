GRIMOIRE WIZARD: STAGING STEPS
==============================
Goal: run the app fully in the cloud, with every laptop switched off.
Staging must be the same infrastructure shape as production, so going to
production means changing connections (URLs, keys, env vars) and nothing
else. No code logic changes.

Notes
- Vendor behavior, free-tier limits and prices are NOT fully verified.
  Cloud Run free-tier numbers below were read from the Google pricing page
  on 2026-11-19; re-check before you commit.
- Derived from the repo as it is today (config.py, main.py, firebase.json,
  environment.prod.ts, Supabase migrations) and PRODUCTION_STEPS.txt.
- Work A -> B -> C -> D -> E. Mark each step [x] when done.


CLOUD CHOICE: GOOGLE CLOUD (NOT AWS)
------------------------------------
Decision: Google Cloud. Reasons:
- Free tier that stays free. Cloud Run has a monthly free allowance that
  resets every month with no end date (request-based billing: 180,000
  vCPU-seconds, 360,000 GiB-seconds, 2 million requests per month).
  AWS's new-account Free plan is $200 of credits for 6 months, and the
  account closes on its own after 6 months or when credits run out unless
  you upgrade. That is a trial, not a free tier.
- Upgrade path with no rework. Free -> paid is the same Cloud Run
  service with different limits. Nothing is re-platformed.
- Already your approved stack: Cloud Run, Firebase Hosting, Secret
  Manager, Gemini (PRODUCTION_STEPS.txt). Staging = production shape.
- Fewer accounts: backend, frontend host and LLM key sit in one Google
  account and one billing account.
- AWS would need a different shape for this backend. EC2 free-tier
  instances are small for two in-process ML models, and the easy
  container service (App Runner) has no free allowance as far as I know.
  Check AWS yourself if you want to compare.

Honest limits of the free tier (plan for these)
- Cloud Run still needs a billing account (card) to be enabled. Set a
  budget alert first. New-customer credits may exist; check.
- Minimum instances = 0 in staging. Free allowance is about 25 hours of
  one 4 GiB instance per month (360,000 / 4 GiB / 3600), so it cannot
  keep an instance warm. Result: the first request after idle is a COLD
  START while the two models load (expect tens of seconds; not measured).
  Production sets min instances = 1, which costs money. That is the
  upgrade.
- Image storage: the image with baked models is probably 2-3 GB. Artifact
  Registry's free storage is small (verify), so expect cents per month.
- Ingestion currently runs inside the upload request (there is no
  background task in main.py). With request-based billing the CPU is
  only guaranteed while the request is open, so keep the request open and
  set a long request timeout. Moving ingestion to a Cloud Run Job is
  Phase 5 of PRODUCTION_STEPS.txt.
- Supabase and Firebase free plans have their own limits (for example
  Supabase can pause an idle free project). Check both before relying
  on them.


THE RULE: ONE IMAGE, ONE BUILD, DIFFERENT CONNECTIONS
-----------------------------------------------------
Staging and production run the same artifacts. Only these change:
  - backend env vars (SUPABASE_*, GEMINI_API_KEY, API_CORS_ORIGINS)
  - Angular per-environment config (apiBaseUrl, supabaseUrl, anon key)
  - Cloud Run settings (min instances, memory, CPU), not code
Staging runs with ENV=production and AUTH_MODE=on. config.py already
refuses AUTH_MODE=off, "*" CORS and localhost CORS origins in production,
so staging proves the production settings really start.


THE INFRA (WHAT RUNS WHERE)
---------------------------
Part   Role                   Staging (now)                Production (later)
----   --------------------   --------------------------   -------------------------
A      Database, auth, files  Supabase project "staging"   Supabase project "prod"
B      Backend API + models   Cloud Run service            Cloud Run service
                              "grimoire-api-staging",      "grimoire-api-prod", same
                              min instances 0              image, min instances 1
C      Frontend (Angular)     Firebase Hosting staging     Firebase Hosting prod
                              site                         site
D      LLM                    Gemini API, staging key      Gemini API, prod key
E      Login                  Google OAuth via Supabase    Same, prod redirect URIs

Everything is a managed cloud service. Nothing depends on any laptop.

Run:
  A  Supabase runs Postgres + pgvector, Auth (Google), Storage bucket
     "documents". You run migrations against it.
  B  We run the backend Docker image on Cloud Run (FastAPI via uvicorn,
     loads all-MiniLM-L6-v2 and the ms-marco-MiniLM-L-6-v2 reranker).
     Cloud Run gives it a public HTTPS URL.
  C  We run "ng build" once and deploy the output to Firebase Hosting.
  D  We run nothing. We only create a key.
  E  We run nothing. We configure Google Cloud OAuth and Supabase Auth.


WHAT EACH PART NEEDS, AND WHERE IT IS STORED
--------------------------------------------
Rule: secrets never go in git, never in the Angular app. Only the
Supabase URL and anon key are public and may go in the Angular config.

A. SUPABASE (staging project)
  Needs                        Stored in
  ---------------------------  ------------------------------------------
  Project URL                  backend env SUPABASE_URL
                               Angular staging config (public)
  anon (publishable) key       backend env SUPABASE_ANON_KEY
                               Angular staging config (public)
  service-role (secret) key    Google Secret Manager, mounted into
                               Cloud Run as SUPABASE_SERVICE_ROLE_KEY
  DB password / access token   your password manager (for Supabase CLI)
  Migrations (4 files)         git: backend/supabase/migrations/
  "documents" bucket           created by the migration, not by hand

B. BACKEND ON CLOUD RUN
  Needs                        Stored in
  ---------------------------  ------------------------------------------
  Dockerfile                   git: backend/Dockerfile
  Docker image                 Google Artifact Registry (same image tag
                               is deployed to staging, then production)
  Secret env vars              Google Secret Manager:
                               SUPABASE_SERVICE_ROLE_KEY, GEMINI_API_KEY
                               (separate secrets per environment)
  Plain env vars               Cloud Run service config (not secret):
                               ENV=production, AUTH_MODE=on,
                               SUPABASE_URL, SUPABASE_ANON_KEY,
                               LLM_MODEL, API_CORS_ORIGINS=<Firebase
                               staging URL>
                               (also keep a copy in a deploy script or
                               GitHub Actions variables, no secrets)
  Model files (HF models)      baked into the image at build time, so the
                               container does not download on each start
  Public API URL               Cloud Run service URL (https://...run.app)
                               -> Angular staging config (apiBaseUrl)

C. FRONTEND (Angular on Firebase Hosting)
  Needs                        Stored in
  ---------------------------  ------------------------------------------
  Firebase project + site      Firebase console; id in .firebaserc (git)
  firebase.json                git: frontend-angular/firebase.json (exists)
  Staging config               src/environments/environment.staging.ts
                               (git, public values only: apiBaseUrl,
                               supabaseUrl, supabaseAnonKey)
  Firebase CLI login / token   your laptop login (later a GitHub Actions
                               secret)
  Build output                 dist/frontend-angular/browser (not in git)

D. GEMINI
  Needs                        Stored in
  ---------------------------  ------------------------------------------
  Separate STAGING API key     Google Secret Manager (GEMINI_API_KEY),
                               mounted into the Cloud Run service
  Model name                   LLM_MODEL in the Cloud Run env vars
                               (gemini-4-hydrogen, same as prod)
  Budget alert / spend cap     Google Cloud billing console

E. GOOGLE LOGIN
  Needs                        Stored in
  ---------------------------  ------------------------------------------
  Google OAuth client ID +     Supabase dashboard > Auth > Google
  secret (staging)             provider (NOT in the repo, NOT in the app)
  Supabase callback URL        Google Cloud console > Authorized
  (https://<ref>.supabase.     redirect URIs
  co/auth/v1/callback)
  Firebase staging URL         Supabase > Auth > URL configuration
                               (Site URL + Redirect URLs). The app sends
                               window.location.origin as redirectTo.

-------------------------------------------------

- main.py run() binds 127.0.0.1:8000; container start must set host and
  port (TODO B).

  values; per-environment Angular config is needed (TODO C).

  Fix it so .env and .venv stay ignored before you commit anything.

  needs a long Cloud Run request timeout until Phase 5 moves it to a Job.
